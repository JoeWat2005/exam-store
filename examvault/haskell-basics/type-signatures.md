# Type signatures

## What this is
`name :: Type` — declare what type a function or value has.

## Mental model
Read `a -> b -> c` as "takes `a` and `b`, returns `c`" (because of currying). Lowercase letters are type variables; uppercase names are concrete types or constructors.

## Syntax
```haskell
double :: Int -> Int
double x = x * 2

-- multi-arg
add :: Int -> Int -> Int
add x y = x + y
```

## Small examples
```haskell
>>> -- ::Lookup in GHCi
>>> :t map
map :: (a -> b) -> [a] -> [b]
>>> :t (.)
(.) :: (b -> c) -> (a -> b) -> a -> c
```

## Exam use
EVERY exam answer starts by writing the type signature verbatim from the template ([P-001](../pitfalls/HIGH-severity.md#p-001) — sig drift = zero marks).

## Common mistakes
- Adding constraints (`Ord a =>`) the template didn't ask for.
- Renaming type variables changes nothing semantically but looks suspicious in marker diffs.
