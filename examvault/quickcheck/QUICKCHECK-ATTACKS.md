## Universal attack list - EVERY function must survive these

These are the input classes the marker reaches for first, regardless of question. Run through this whenever you've written ANY function.

| # | Attack | What the marker tries | Why you fail | Cheap fix |
|---|--------|----------------------|--------------|-----------|
| U1 | Empty input | `[]`, `Empty`, `Branch []`, `Nothing`, `""`, `(0,0)` | Pattern-match exception, or wrong-default return value (`0` vs `[]` vs `True`) | Add explicit base case as the FIRST pattern |
| U2 | Singleton input | `[x]`, `Leaf x`, `Branch [Leaf x]`, `Just x`, `[c]` | Off-by-one — your recursive case fires on `n=1` and assumes `n>=2` | Make sure base case fires on length 1, not just length 0 |
| U3 | Duplicates | `[1,1,1]`, BST containing same key twice, repeated `tell` writes | `nub`-style assumptions; "insert if not present" silently overwrites | Decide BEFORE writing whether dupes are allowed and document with a comment |
| U4 | Sorted input | `[1,2,3,4,5]` | Hides a bug where you rely on randomness — e.g. `sort . reverse` looks right on sorted | Test on `[3,1,4,1,5,9,2,6]` mentally |
| U5 | Reverse-sorted | `[5,4,3,2,1]` | Skewed trees from inserting in order; stack overflow on deeply right-leaning recursion | Don't write inherently left-recursive accumulators if input is generated by repeated `insert` |
| U6 | Huge / deep input | Mock Q1 uses `sized` up to ~10 levels; Q5 uses depth 18 for And-only | Non-tail-recursion blows the stack | Often fine, but watch for `foldr` on a 100k list |
| U7 | Exact type signature | Marker imports your module `qualified as Student`; signature mismatch = no marks | `Eq a =>` vs `Ord a =>` vs `Num a =>` | **Copy the signature character-for-character** from the template |
| U8 | Negative integers | `-3`, `n < 0` in `take`/`drop`/recursion | Infinite recursion / wrong base case | Add `n <= 0` guard, not just `n == 0` |
| U9 | Boundary at 0 | `n = 0`, `replicate 0 x`, `applyNTimes _ _ 0` | Often the base case the marker tests *first* (see Mock Q2: `applyNTimes mx mf 0` must return `pure [x]`, not `pure []`) | Carefully read the spec — `0 times` does NOT always mean "no result" |
| U10 | Pre-marked `IfFail` cascade | If your main test fails, marker runs a *weaker* test for partial credit. You can score 0 on the main but still pick up the partial. | You panic and rewrite everything | If the main 8-mark test fails, look at the `IfFail` test — usually it's "correct shape but pointer/order wrong" |

## The "before you click submit" 60-second checklist

Print this. Read every line out loud before you submit:

### Compile checks (don't even open ghci if these fail)

- [ ] File compiles plain: `ghc -fno-code MockTest.hs` (no errors, no warnings about incomplete patterns)
- [ ] File compiles with safe mode: `ghc -XSafe -XNoGeneralizedNewtypeDeriving -fno-code MockTest.hs`
- [ ] `{-# LANGUAGE Safe #-}` pragma at top is **still there** (don't delete it)
- [ ] Module name matches filename exactly (e.g. `module MockTest where` in `MockTest.hs`)
- [ ] No `import Data.Map` / `Data.Set` / `Data.Sequence` / `System.*` — only the allowed imports
- [ ] `presubmit.sh AssignmentN` exits 0

### Signature check (instant fail otherwise)

- [ ] Every function signature is **character-for-character identical** to the template. Copy-paste, don't retype.
- [ ] No accidental constraints added (`Ord a =>` where the template said no constraint)
- [ ] No accidental constraints removed (the marker will try to instantiate at a non-Ord type if you removed it)
- [ ] `where`-helpers are below the function, not in the type signature

### Universal edge cases

- [ ] `[]` / `Empty` / equivalent base case is handled and tested in ghci
- [ ] Singleton case tested
- [ ] Function does not call `head`/`tail`/`last`/`init`/`!!` without a pattern-match check first
- [ ] If function does arithmetic: tested with `0`, negative, large number
- [ ] If function uses `div`/`mod`: divisor is provably non-zero or guarded
- [ ] If function recurses on a number: handles `n = 0` AND `n < 0`
- [ ] If function uses `do` over Maybe/State/Writer: actually returns in the right order

### Spec re-read

- [ ] Re-read the problem statement (the actual text) one more time
- [ ] Re-read the function's docstring / Haddock comment if any
- [ ] Re-read the type signature one more time
- [ ] For "is X" predicates: ask yourself "does Empty satisfy X vacuously? Is it `True` or `False`?" (BST: `True`. Sorted: `True`. Balanced: `True`. Magic square: only for 1x1 by spec.)

### File hygiene

- [ ] No `undefined` left in the file
- [ ] No `error "todo"` left in the file
- [ ] No commented-out junk that might confuse the parser
- [ ] No top-level `import Test.QuickCheck` (it works on vLab but pollutes Safe Haskell)

## How the marker actually structures tests

From reading `MockTestMarking.hs` and the three assignments, every test follows this pattern:

```haskell
testName = Test
  { mark        = getMarks (Marks N)
  , description = "Checking that 'foo' handles ..."
  , successMsg  = "You got N because ..."
  , failMsg     = "Your 'foo' did not ..."
  , prop        = makeUnaryPropWith propFoo generator shrinker
  , condition   = Always | IfFail otherTest | IfSuccess otherTest | All [...] | Any [...]
  }
```

**Critical:** the `condition` field means the marker has a *cascade*:

- `Always` runs always.
- `IfFail t` runs only if test `t` failed → this is **partial credit fallback**. If you fail the strict 8-mark test, you may still pick up a 4-mark "you got the shape right but pointer is wrong" test.
- `IfSuccess t` runs only if `t` passed → this is **gating**. If you fail the base case test, the marker won't even run the recursive case test.

**Implication:** if your base case is broken, you lose every dependent test. Get base cases bulletproof first.

## Patterns to look for in the test files (so you know what's coming)

| Pattern in test file | Means in practice |
|---|---|
| `makeNullaryProp prop_X` | A property that takes NO generated input — it's a hardcoded test like `gameOver (0,0) == True` or three named magic squares. Fix THESE first; they're cheap marks. |
| `makeUnaryPropWith p gen shrink` | Standard one-argument test. The `gen` shows exactly what shape input the marker uses — read it. |
| `makeBinaryPropWith p gen shrink` | Two arguments combined into a tuple. Often `(value, structure)` pairs. |
| `genWriter`, `genHelperNBranchingTrue`, etc. | **Read the source!** These tell you exactly what counterexamples will be small. |
| `~=` everywhere | The marker uses `deepseq` on both sides — meaning an `error "todo"` in part of your output triggers as a counterexample, not a silent pass. |
| `counterexample errMsg False` | Custom failure message. When the marker tells you "Your output was X but the expected output is Y", that's this. |
| `monadicIO $ do ... catch ...` | Tests that an exception IS thrown (Assignment 1 grid moves, "cover throws on uncoverable"). Forgetting to `error` when you should = lose marks. |
| `p_permOf x y` | "x is a permutation of y" — order doesn't matter (Mock Q2 `applyNTimes_outOfOrder`, Q4 trace all-states). |
| `p_seteq x y` | "x and y have the same elements as sets" (Assignment 2 ramify/tabulate). |
| `forAll (chooseInt (1, 10)) $ \n -> ...` | The exam uses bounded random ints. You will NOT be tested with `n = 999999`. |

## Surprising patterns I found in the marking scripts

These are easy to miss without reading the source:

### 1. The marker re-imports YOUR solution module qualified as `Student`

```haskell
import qualified MockTest as Student
```

If you rename anything or shadow a Prelude function with a different signature, the marker can't find it. **Don't rename.**

### 2. The marker uses `deepseq` to force errors out of laziness

```haskell
student' = deepseq student student
```

If your function returns a tuple where ONE field is `undefined`, you do not pass. You can't lazily skate by.

### 3. Mock Q2 generates `n` starting from 2 to give partial credit

```haskell
((,) <$> genWriter <*> chooseInt (2, 10))
-- comment in source: "generate from 2 so students that index from 0 can still get some partial marks"
```

So if your `applyNTimes` is off-by-one but consistent, you still score on the recursive test even if you fail the base case test. **The marker is generous on off-by-one if the recursion is structurally right.**

### 4. Mock Q3 `gameOverComplete` is a NULLARY property — a single hardcoded test on `(0,0)`

```haskell
prop_gameOverComplete = let (p, _) = runState Student.gameOver (0, 0) in p ~= True
```

It is literally just "does `gameOver` return True on `(0,0)`?". Four marks. Free if you remember it.

### 5. Mock Q5 `circuit` is checked SEMANTICALLY, not structurally

```haskell
tryToRefuteEquivalence c e =
  catMaybes $ (\ctx -> if semCirc c ctx == semExpr e ctx then Nothing else Just ctx)
              <$> allSublists is
```

The marker tries every assignment of T/F to every variable mentioned. Your circuit just needs to AGREE with the expression on every input. So even a verbose circuit that's correct scores full marks. **Don't try to "optimise"** — get correctness first.

### 6. Assignment 2 `prop_decodeText_word = prop_decodeText` — same test, different input

```haskell
prop_decodeText_word :: Code -> Property
prop_decodeText_word = prop_decodeText
```

The "fallback" test for partial credit runs the SAME property with a SIMPLER generator (single word instead of multi-word text). This is the classic cascade.

### 7. The shrinking strategy reveals the bug pattern

Mock Q1: `shrinkNandTreeTrue` keeps only subtrees that ARE n-branching. So when you fail, the counterexample shown is the smallest n-branching tree you misclassified. Don't be fooled by "oh that's a small tree, my function should work on that" — it's small because the marker shrank it from a big counterexample.

### 8. Custom `Show` instances in the test files give you human-readable counterexamples

```haskell
instance Show Q2Wrapper where
 show (Wrap mx) = let n = fst $ runWriter mx
                  in "do { tell [" ++ show n ++ "] ; pure " ++ show n ++ " } "
```

When the marker fails your Q2, it tells you "for `do { tell [7] ; pure 7 }`, your output was X". That's the marker. Read the message.

## "When in doubt, what's the most defensive base case?"

| Type | Defensive base | Why |
|------|---------------|-----|
| `[a] -> Bool` predicate | `f [] = True` (vacuous truth) | All predicates over an empty collection are True unless spec says otherwise |
| `[a] -> Bool` "is non-empty and ..." | `f [] = False` | Spec explicitly says non-empty |
| `[a] -> [a]` transform | `f [] = []` | Identity on empty |
| `[a] -> Int` count | `f [] = 0` | Zero count |
| `[a] -> a` extract | `f [] = error "..."` is OK because spec disallows | Don't pretend `f [] = undefined` is OK; the marker calls `deepseq` |
| `Tree a -> Bool` | `f Empty = True` | Same as list-Bool — VACUOUS TRUTH |
| `Tree a -> Tree a` | `f Empty = Empty` | Identity |
| `Tree a -> [a]` flatten | `f Empty = []` | Empty list for empty tree |
| `Maybe a -> ...` | Handle `Nothing` explicitly with `case` or pattern | Don't `fromJust` without a guard |
| `m a` monadic recurse on `n` | `n <= 0` returns `pure baseValue` | Use `<=` not `==` for safety |
